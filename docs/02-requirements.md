# Требования по Вигерсу

## Бизнес требования

| ID | Требование |
| -- | ---------- |
| BR-1 | За 6 месяцев перевести 50% записей в онлайн. |
| BR-2 | Снизить число неявок до 8%. |

## Пользовательские требования

| ID | Требование |
| -- | ---------- |
| UR-1 | Как пациент, я хочу иметь возможность просматривать свободные талоны, чтобы выбрать время записи. |
| UR-2 | Как пациент, я хочу иметь возможность отменить запись, чтобы не было неявки на приём. |
| UR-3 | Как регистратор, я хочу иметь доступ к записям пациентов, чтобы отменять и переносить их записи. |

## Функциональные требования

| ID | Требование |
| -- | ---------- |
| FR-1 | Система должна отображать список свободных талонов к выбранному специалисту. |
| FR-2 | Система должна бронировать слот при успешной записи к врачу. |
| FR-3 | Система должна закрывать направления пациентов, с даты выдачи которых прошло >30 календарных дней. |
| FR-4 | Система должна блокировать функцию отмены записи, если до приёма осталось менее 2 часов. |
| FR-5 | Система должна блокировать функцию записи пациенту, если в течение 3-х последних месяцев он не явился на приём ≥2 раза. |
| FR-6 | Система должна проверять прикрепление пациента к поликлинике при записи к врачу-терапевту участковому. |
| FR-7 | Система должна проверять наличие выданного направления терапевтом пациенту к кардиологу и неврологу, а в случае наличия отобразить доступные талоны к ним. |
| FR-8 | Врач должен быть способен просматривать список записанных к нему пациентов. |
| FR-9 | Врач должен видеть историю болезни каждого пациента, который был у него на приёме. |
| FR-10 | К записавшемуся пациенту должны приходить уведомления о записи в ЛК, затем в SMS. |
| FR-11 | Система должна давать возможность пациенту указывать причину записи к врачу. |

## Нефункциональные требования

| ID | Требование |
| -- | ---------- |
| NFR-1 | Длительность сессии должна составлять 30 мин. |
| NFR-2 | Передача данных должна осуществляться по протоколу HTTPS. |

## Внешние интерфейсы

| ID | Требование |
| -- | ---------- |
| EI-1 | Макеты должны покрывать версию для ПК (n px) и мобильную версию (m px). |
| EI-2 | В SMS информативный текст допустим только на кириллице. |

## Ограничения

| ID | Требование |
| -- | ---------- |
| CON-1 | Бюджет - y млн руб. |
| CON-2 | Релиз MVP - через z месяцев. |
| CON-3 | Требования утверждаются после согласования с заказчиком. |
